# 方法与接口

## 1. 我们的设定：只有 RGB 的生成式游戏

Matrix-Game 类模型输出 RGB 视频，而不是可直接使用的游戏引擎三角网格。本实验把已生成/观察到的一张 RGB 输入 MoGe-2，预测当前视角的稠密点图和深度。它是**2.5D、单视角、带误差的几何先验**，不是完整三维世界，也不是把 Matrix-Game 当成 3D 重建模型。

背景被遮挡的部分、尚未看到的物体背面不在这个点图中；新视角显露的区域仍需填充或生成。无需先训练在线 3DGS，并不意味着消除了几何预测成本或补全问题。

如果后续能接入引擎，可把同一接口的生产者替换为 Depth/G-buffer；那是另一种可获得真值状态的设定，不能和 RGB-only 主结果混为一谈。

## 2. `geometry.npz` 接口

| 字段 | 形状 | 含义 |
|---|---|---|
| `points` | H×W×3, float32 | 源相机坐标中的点图 |
| `depth` | H×W | 源相机 z 深度；不是射线距离 |
| `mask` | H×W, bool | 模型给出的有效性；不是已校准质量概率 |
| `intrinsics` | 3×3 | 归一化内参 K |
| `normal` | H×W×3 或空数组 | 模型输出法线 |
| `rgb` | H×W×3, uint8 | RGB，而不是 OpenCV 的 BGR |
| `coordinate_convention` | 字符串 | x 向右、y 向下、z 向前 |

预测尺度不能直接视作游戏真实米制。合成实验中的 `--forward 0.10` 是预测尺度下的数值；玩家移动速度与此尺度之间尚未标定。

## 3. 相机变换与投影

设源点为 `X_s`，目标相机在源坐标系中的位置为 `C_s`，目标相机到源相机的旋转为 `R_c2s`：

```text
X_t = R_c2s^T (X_s - C_s)
u = W * (fx * X_t.x / X_t.z + skew * X_t.y / X_t.z + cx) - 0.5
v = H * (fy * X_t.y / X_t.z + cy) - 0.5
```

CPU/CUDA 两种实现均保留目标视角 `z > 1e-4` 的点。正 yaw 表示向右转；正 pitch 表示向下看。命令行的 right/down/forward 是**源相机坐标中的平移分量**，不是已实现的游戏控制器。

固定 `splat_radius=1` 时，一个点覆盖 3×3 邻域，使用最小目标深度处理可见性。CUDA 用 `scatter_reduce(amin)` 得到深度，再从近似等深候选中取确定性的颜色索引；其 `isclose` 容差可能造成与 CPU 的细微颜色差异，不保证逐 RGB 位一致。

Coverage 仅表示有点落入；扩大 splat 半径可以增加覆盖，也可能造成边缘扩张、前景污染和错误颜色。它不等于可直接复用的比例。

## 4. 目标帧实验中的位姿从哪里来

展示视频没有相机轨迹。离线实验使用源/目标帧的 SIFT 匹配，将源帧 MoGe 点和目标图像坐标送入 PnP：

- SIFT 最多 5,000 特征，Lowe ratio 0.75。
- EPNP RANSAC：500 次迭代，3 px 阈值，置信度 0.999。
- LM 优化只有在误差有限且中位误差不超过 RANSAC 的 1.05 倍时接受。
- 最终匹配内点中位重投影误差超过 5 px 则拒绝。

`X_t = R_s2t X_s + t_s2t` 转成 Warp 输入：`R_c2s = R_s2t^T`，`C_s = -R_c2s t_s2t`。

这不是相机真值；PnP 残差只反映被选匹配的一致性。它也依赖未来目标 RGB，不能在生成该帧之前作为在线输入。因此当前实验回答“给定目标辅助位姿时 Warp 的表现”，没有解决玩家 action → pose。

## 5. 指标与三个容易混淆的 Oracle

PSNR：Copy 与 Warp 都在同一帧对的 Warp 有效区域上评估，先按帧对求 PSNR，再等权平均；不是把全部像素汇总后求一次 PSNR。不同 Warp 的覆盖区域也可能不同。

Tile test：16×16 tile；Warp 覆盖至少 95%，且覆盖区域平均 RGB-MAE 不超过阈值。阈值为 10/20/30/40（像素量纲 0–255）。边缘残缺 tile 仍各算一块；640×294 有 760 块。因此块比例不严格等于像素面积比例，更不自动等于 DiT latent token 比例。

| 名称 | 实际做法 | 是否需要目标帧 |
|---|---|---|
| 目标辅助位姿 | 源几何 + 源/目标特征 → PnP | 是 |
| Legacy pixel-min oracle | 每个像素取 Copy/Warp 较低误差，再做 tile 平均 | 是 |
| Tile-choice oracle | 对每块分别测试 Copy、Warp，任一候选通过即可；不混合像素 | 是 |

这些是离线诊断，不是训练好的路由器，也不是“人眼看不出错误”的保证。动态事件、HUD、物体身份和交互正确性都需要额外指标。

## 6. 耗时模型的边界

`T(r)` 是 active-Q 结构代理的实测中位数插值；不是训练后的 DiT。假设每 K 帧有一张完整 4-step anchor，其余采用 0/4 路由：

```text
B = 4 T(1)
C_avg = [B + G + (K-1) * (W + 4 T(1-f0))] / K
speedup_proxy = B / C_avg
```

纯 Copy 分支设 G=W=0。K=8 示例把 gap=8 的离线通过率用于所有非 anchor 帧；真实周期里年龄为 1…7，并没有采集相应的在线分布。表中还采用 `T(mean(r))`，不等于每帧 `T(r)` 的平均。

大代理最小实测比例为 12.5%。新版 `floor` 在 `0<r<12.5%` 保持该点延迟；旧版 `legacy_linear` 连到原点，可能严重乐观。`r=0` 才假设完全跳过。floor 也只是敏感性假设，不是证明的上界。

VAE、K/V 构建/维护、路由、传输/同步、动态处理、修复模型、合成、显示、输入排队等均未完整计入。表中毫秒值不能当作实际运行帧时间，更不能换算成真实实时 FPS。
