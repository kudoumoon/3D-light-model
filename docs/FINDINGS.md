# 结论与研究路线

本文件按研究证据类型区分已知和待验证内容。

## Fact：已观察到的结果

- 单 RGB 的 MoGe-2 点图可以启动重投影；当前链路并不依赖在线 3DGS 优化。
- GPU Warp 在本地 GTA 样本上为 3.693 ms，而 NumPy 为 212.207 ms。
- 几何推理约 59 ms/张，不能忽略，也不能假定每帧都免费获得。
- 在这两个短演示裁剪中，Copy 平均质量高于固定使用 Warp；不同局部像素存在互补。
- 真正逐块 Oracle 的 gap8 阈值通过率提升比旧逐像素 Oracle 小。
- 大结构代理能从减少 active Q 获益，小代理没有可靠缩放收益。
- 没有运行真实 AR-DiT 端到端加速系统；现有账本里几何分支也没有击败 Copy 基线。

原始数据和计算见 [实验记录](EXPERIMENTS.md)。

## Inference：由现象得到的设计判断

1. 应先做 Copy/Whole-chunk bypass，再检验几何是否提供额外收益。若只和“每帧全量生成”比较，会混淆时间复用收益与三维贡献。
2. 几何适合低频刷新可信 anchor，或由已有模型特征预测轻量头；它不应无条件出现在每帧关键路径上。
3. Warp 的启用依据应该包含运动幅度、几何置信度、遮挡和材质/动态风险，而不是覆盖率一个数。
4. 显示暂存状态与可写入长期 AR 历史的状态应分开，避免误差自回归传播；这点尚未实现。

## Hypothesis：下一版值得验证的最小系统

先只实现四路控制器：

- `Copy`：低位移、低事件风险、短历史年龄。
- `Warp`：相机位移明显、几何/位姿一致、静态不透明区域。
- `Repair`：少量遮挡或残差，用经过训练的轻量修复/少步模型。
- `Regenerate`：大反遮挡、动态事件、低置信度或恢复 anchor。

首个可行目标不是完整“三维世界建模”，而是在可测输入条件下验证几何路由相对强 Copy 的 Pareto 改善：同质量更低耗时，或同预算更高质量。

## Risk：目前最可能失败的地方

- 预测深度的尺度、相机位姿和动作映射彼此不一致。
- 动态车、人、HUD、水面、镜面和粒子不能由静态点图正确解释。
- 3×3 splat 只是扩大支持，并没有恢复真实纹理。
- RGB warp 不等价于 VAE latent warp；几何变换后 latent、noise level、KV 位置可能不兼容。
- 路由网络的误放行可能比均方误差更影响交互体验。
- GPU 频率、launch-bound 负载、同步与跨模型显存争用可能吃掉理论节省。

## Experiment：按优先级推进

| 阶段 | 要做什么 | 主要比较 | 进入下一阶段的条件 |
|---|---|---|---|
| P0：干净评估数据 | 无转场、无按键叠层，记录 action 和相机/引擎真值 | 真值几何/位姿 vs 预测几何/位姿 | 能区分几何、位姿、动态错误 |
| P1：Warp 本体 | radius0/1、深度边界约束、多关键帧、动态 mask | Copy、2D flow、同预算 Warp | 在预设质量指标上有增量收益 |
| P2：因果路由 | 只使用历史 RGB/几何、当前 action、历史年龄 | 规则路由、学习路由、离线 Oracle | 测试集误放行受控，耗时小于收益 |
| P3：真实模型 | L40/H100 接入当前使用的 AR-DiT | 全量、Copy bypass、无几何复用、完整方法 | 实测端到端 Pareto 改善 |
| P4：长期交互 | 回头、碰撞、快速转向、开门、动态遮挡 | 不同 anchor/历史提交策略 | 长时一致性与 p95/p99 不退化 |

建议预先固定可证伪门槛，例如在相同画质/事件正确性约束下 ≥1.25× 端到端加速且 p95 交互延迟降低 ≥20%；这是**建议的实验目标，不是已达成结果**。

可部署输入必须是当前/过去信息；任何读取未来 RGB、未来 pose 或目标误差的模块都只允许作为 offline oracle。训练与评估按完整场景/轨迹划分，不按相邻帧随机切分。
